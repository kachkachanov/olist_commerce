E-commerce Analytics: Olist Marketplace

Аналитический проект на реальных данных бразильского маркетплейса Olist (100k+ заказов, 8 связанных таблиц). Цель — пройти полный цикл продуктовой аналитики: от валидации данных до дизайна A/B-теста.

Стек: PostgreSQL, Python (pandas, numpy, statsmodels), Redash, Yandex DataLens.


Блок 0 — Инженерный фундамент


Подключение к PostgreSQL через SQLAlchemy, загрузка 8 таблиц
Профилирование качества данных: типы, количество уникальных значений, доля NULL по каждой таблице
Проверка целостности: заказы без оплат, дубликаты order_id
Отсечение выбросов по цене (IQR по группам category_name) и формирование очищенного набора заказов
Анализ динамики выручки по месяцам, абсолютный и MoM-прирост
MAU по уникальным покупателям (customer_id) с месячной группировкой


Результат: очищенный и провалидированный набор данных для дальнейшего анализа, выявлены и устранены выбросы в ценах и сроках доставки.


Блок 1 — Продуктовое ядро


ABC-анализ категорий по выручке: кривая Парето, классификация A/B/C по накопительному проценту
XYZ-анализ: коэффициент вариации месячного спроса по категориям, классификация X/Y/Z
Объединённая ABC-XYZ матрица


Вывод: 12 категорий из класса A (~75% выручки) попадают в XYZ-класс Z — высокая ценность при низкой предсказуемости спроса. Это указывает на необходимость динамического подхода к управлению запасами вместо плановых закупок.


Геоаналитика: агрегация заказов и выручки по штатам, подготовка данных для карты в DataLens
Выгрузка очищенных метрик для дашбордов



Блок 2 — Клиентская аналитика (RFM)


Расчёт RFM на уровне customer_unique_id: Recency, Frequency, Monetary
Доля повторных покупателей: (Frequency > 1)
Сегментация по квантилям (R и M через qcut, F — бинарно: разовая/повторная покупка)
Кастомная сегментация на основе RFM-скоров: Champions, Potential Loyalists, New Customers, Big Spenders at Risk, Lost, Regular
Сравнение выручки и среднего чека по сегментам


Вывод: подавляющее большинство клиентов совершают только одну покупку — это системная характеристика датасета (разовый маркетплейс-трафик), а не аномалия. Найдена группа Champions с высоким Recency, Frequency и Monetary — приоритетный сегмент для удержания.


Блок 3 — Дизайн A/B-теста


Обоснование прокси-метрики: Repeat Purchase Rate вместо review_score или конверсии
Расчёт baseline RPR на реальных данных
Расчёт MDE (минимальный значимый эффект, относительный +15%) и объёма выборки через statsmodels.stats.power
Стратифицированное сплитование пользователей по штату (state) на контроль/тест
SRM-check (проверка равенства групп)


Результат: baseline RPR ≈ 2.96%, что согласуется с retention из Блока 0. Требуемый объём выборки на группу — ~24.5k пользователей, фактически доступно ~43k — запас достаточен. SRM-check подтвердил корректность сплитования (p-value 0.77, группы сбалансированы).
